### 0.2 你需要回答的核心问题 (15 个)

按重要性降序:

**P0 — 战略层 (3 个)**
1. **"全对齐 Multica"决策本身**是否合理? Multica 的 5 维抽象对 Loom 的本地优先身份是否有内部冲突? spec §1.4 列举的"我们不改的边界"够不够?
2. **Sandbox 层选 AgentENV** 是否合理? 有无其他更优选项 (E2B Cloud / Fly Machines / kata-containers / gVisor / 自研)? macOS 部署约束 (AgentENV 不支持 macOS 主机) 是否会破坏 v2.0 价值?
3. **6 阶段 25 天** 时间表是否现实? 哪个阶段的"风险"被低估了? 哪个被高估了?

**P1 — 架构层 (6 个)**
4. **Skill 系统**: 4 个导入源的限制 (registry/git/local/inline, 禁 marketplace) 是否过度? ClawHavoc 三大防御是否足够? `scope=local` 默认是否会让 Squad 难以复用 Skill?
5. **Squad 抽象**: 引入 Squad 替换 v0.3 Team 是否值得? leader 协议 + anti-self-loop 是否过度设计? v0.3 不变量 #2 (每团队一个 Main Agent) 重写是否丢失了什么?
6. **3rd-Party CLI 适配**: 14 个 CLI 3 档优先级 (P0/P1/P2) 划分是否合理? P2 档 6 个 CLI 的"最小支持"承诺是否会变成"半成品"拖累质量?
7. **3-Token 认证**: UserToken/DaemonToken/RunToken 拆 3 层是否过度? macOS Keychain 集成的 SDK 依赖 (Security Framework) 是否有 Go 绑定? RunToken 5 分钟寿命是否太短? 1h 上限是否太长?
8. **MCP Broker**: 不自实现 MCP 协议的决定是否正确? 11/14 CLI 不真用 MCP 的现实是否意味着 v2.0 砍掉 MCP 也能活?
9. **数据模型迁移**: WorkItem → Issue + Task 拆分 + 90 天兼容期是否合理? 90 天后 v1 WorkItem 表删除的策略? 迁移脚本的回滚能力?

**P2 — 实施层 (4 个)**
10. **回退路径 (--no-sandbox)**: 是否在所有 Phase 都有效? Phase 2.D 强制 sandbox 后, 回退 v1.x 的触发器 (3 硬回滚条件) 是否充分? 有无遗漏的"灰色场景"?
11. **测试策略**: spec 没有测试章节。Phase 2.A-E 各阶段的测试覆盖率目标? 集成测试? 模糊测试 (fuzzing) 范围? Loom 已有 `.loom-evidence/` 实践, 如何延续?
12. **可观测性**: spec 没提 metrics / logging / tracing。AgentENV 自带 ublk daemon metrics (`:9103`), Loom daemon 应如何聚合? 看板 (Observation / Cost / Governance 三视图) 与 v2.0 数据模型的衔接?
13. **性能预算**: spec 没提 SLA。Loom v0.3 假设 5min dispatched / 2.5h running / 6 并发 (来自 Multica)。v2.0 自身目标? AgentENV <50ms boot 的承诺能否保留到 Task 调度链路?

**P3 — 上下文层 (2 个)**
14. **Multica 已知的限制** (Cloud waitlist / 自托管 docker 门槛 / MCP 1/11) 哪些 Loom 在 v2.0 仍然继承了? 哪些真正避免了?
15. **未明说的假设**: spec 有哪些隐含假设? 例如: 假设 Provider 凭证一定能存 Keychain (企业 MDM 环境呢?); 假设 User 是单人 (团队场景呢?); 假设 daemon 永远在跑 (笔记本休眠呢?)

### 0.4 评估的硬规则

1. **必须给证据**: 每个结论引用 spec 行号 / 外部文档 / 你的推理。空话 = 0 分。
2. **必须独立思考**: 不要复述 spec 自己写的"风险与回滚"。要指出 spec **没意识到**的风险。
3. **不要客气**: spec 是 lune + mavis 写的, 你可以说"§2.4 整章需要重写"如果真需要。
4. **承认不确定**: 你不是全知。`grep` / `web_search` / `web_fetch` 用起来。不确定的事说"我不确定,需要 X 验证"。
5. **不要写代码**: 你在评估 spec, 不是在改 spec。改 spec 是 lune 的事。
6. **输出长度**: 报告 8K-15K 字节。少于 5K = 太浅; 多于 20K = 太啰嗦。
